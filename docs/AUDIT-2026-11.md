# Audit, 2026-11-06

Scope: whole repository at commit `2fc83ae` (backend, frontend, Docker, rclone sidecar, docs). Read the code, ran the 183-test suite
(all pass, about 11 s), and ran the app in a scratch folder to watch it work. Not covered: a real browser pass, real Docker build,
real rclone to a real remote, YouTube downloads, load testing.

See also the full specification in [SPEC.md](SPEC.md), which carries these findings forward and adds more (N1 to N14 there).

## Verdict

The app works the way the local-first design says it should. The Google Sheets/Drive code is gone; the only Google traces left are
names. The backend is cleanly layered and the event types are data, so it is easy to extend. The weak spots are the cloud-sync
sidecar (not multi-event aware), the frontend (three very large vanilla JS files, public CDNs at runtime) and scattered feature switches.

## How it works (answers to the original questions)

1. **Google is gone from the app.** Data is in SQLite, files are on local disk. Cloud copy is an optional rclone container.
2. **Deployment** matches your description: one volume (`./events`), one subfolder per event, created from `/admin`.
3. **"The database holds it all together": partly.** There is no central database. Each event has its own `event.db`. Tracks are tied to acts by the **entry id in the file name**, and the database only caches the file name and a version. The folder wins for tracks (re-scanned every few seconds). Nothing in the database links one event to another.
4. **Modular?** Backend yes, frontend moderate, feature switches no (see findings).

## Findings

Severity: **High** = breaks the stated plan. **Medium** = real risk or real friction. **Low** = tidy-up.

| # | Sev | Finding | Where | Suggested fix |
|---|---|---|---|---|
| 1 | High | **rclone sidecar does not follow the active event.** It mirrors `events/$EVENT_ID` from `.env` only. After switching or creating an event in `/admin`, the new event is never copied to the cloud, and the app itself ignores `EVENT_ID` once `.active_event` exists. | `rclone/sync.sh:15-16`, `app/config.py` (active-event override), `docker-compose.yml` | Sync the whole `events/` root to `RCLONE_REMOTE` (each event becomes a subfolder), and pull `<remote>/<event>/incoming` for every event, or at least re-read `.active_event` each loop. Add a test using a local rclone remote. |
| 2 | Medium | **Browsers need the internet.** Tailwind (`cdn.tailwindcss.com`, a dev-only script), Lucide (`unpkg.com/lucide@latest`, unpinned), WaveSurfer (`unpkg.com/wavesurfer.js@7`) and `marked` (jsDelivr) load from public CDNs on every page. The service worker precaches them for `/console` only. A LAN-only venue gets unstyled pages and no waveform. ADR 0001's "offline-capable" is true for the server, not the browser. | `app/static/*.html`, `app/static/sw.js` | Vendor pinned copies under `app/static/vendor/`, precompile Tailwind to one CSS file (CLI, build step in the Dockerfile), pin versions. |
| 3 | Medium | **Feature switches are scattered.** `get_setting(key, getattr(settings.signup, key, True))` appears 92 times across routers and services. `console_enabled` alone is referenced in 9 non-test files. Adding a switch touches 6 to 8 places. | `app/config.py`, `presets.py`, `admin_service.py`, `event_manager.py`, `routers/*` | One flag registry (key, default, label, public yes/no) that the others read. Add a `require_flag("x")` dependency instead of inline checks. |
| 4 | Medium | **Frontend is monolithic.** `admin.js` 2,246 lines, `intake.js` 2,043, `admin-settings.js` 1,930, plus large inline HTML. No modules, no build, no JS tests. Works, but a design refresh will touch everything. | `app/static/js/` | Before the redesign: split by feature into ES modules, move shared fetch/escape helpers into `utils.js`, add a handful of browser smoke tests (Playwright). |
| 5 | Medium | **Schema "migrations" are try/except `ALTER TABLE`.** No version number, so a breaking change cannot be detected or ordered. Failures are swallowed. | `app/repositories/schema.py` | Add `PRAGMA user_version` and numbered steps; log failures other than "duplicate column". |
| 6 | Low | **Dead Google-era names and code.** Columns `drive_file_id`, `drive_file_name`, `created_via` default `'sheet'`; unused `ColumnNamesConfig` and all `COL_*` env vars; `push_to_sheet` / `pushed_to_sheet` in the reorder API; `/api/sync` (really "export now"); `backup_target_sheet`; `sheet_url` / `signup_sheet_url` (this one is a legitimate "external link" setting, just badly named). | `config.py`, `schemas.py`, `routers/stage.py`, `backup_service.py`, `schema.py` | Rename in one change with a database migration and a UI sweep; delete `ColumnNamesConfig`. |
| 7 | Low | **Dead, dangerous code:** `DBService.reset_database()` drops every table and has no callers. | `app/services/db_service.py` | Delete it. |
| 8 | Low | **Pass-through facade.** `db_service.py` (372 lines) mostly forwards to the repositories "for backward compatibility"; `main.py` re-exports a long list of schemas for the same reason. | `db_service.py`, `main.py` | Move callers to the repositories gradually, then remove. |
| 9 | Low | **Stream and track-info assume `.mp4` is the only video.** Dropped-in `.mov`, `.webm`, `.mkv`, `.m4v` are accepted as media but served as `audio/mpeg`; `.wav`/`.flac`/`.m4a` get `audio/mpeg` too. App uploads are always converted to mp3/mp4, so only hand-delivered files are affected. | `routers/audio.py`, `audio_service.py` | Use `mimetypes` plus `media_type_for`. |
| 10 | Low | **Session cookie never changes.** It is an HMAC of the PIN, valid until the PIN changes (the 24 h `max_age` is browser-side only). Rate-limit key trusts `X-Forwarded-For`; the global cap of 100 failures can lock the admin out for 5 minutes. Acceptable for this audience, worth knowing. | `routers/auth.py` | Add a server-side expiry stamp to the token if it ever faces the public internet. |
| 11 | Low | **Branding hard-coded in places.** FastAPI title, downloader title, `config.yaml` defaults, SW cache name `paattukoottam-console-v1`. Fine for EMA; matters for re-skinning. | `main.py`, `downloader/main.py`, `config.yaml`, `sw.js` | Read from event settings. |

## Modularity score

| Area | Rating | Why |
|---|---|---|
| Backend layering | Good | routers -> services -> repositories; in-process event bus for cross-cutting reactions; 8 presets are plain data |
| Storage contract | Good | One folder per event is the whole contract; easy to copy, archive, sync |
| Adding/removing a feature switch | Fair | 6 to 8 files; the README now lists them |
| Downloader | Good | Separate container, one small HTTP API, optional |
| Frontend | Fair | No framework or build is a feature for simplicity, a cost for size; three files over 1,900 lines |
| Tests | Good | 183 tests, about 4,000 lines; no browser or sidecar tests |

## Suggested order of work

1. Fix finding 1 (cloud sync across events). It is the one thing that breaks the plan you described.
2. Vendor the CDN assets (finding 2) before the design refresh, so the polish does not depend on the venue network.
3. Do the flag registry (3) and frontend split (4) together with the redesign.
4. Rename the Google-era fields (6, 7, 8) in one tidy change with a migration (5).
